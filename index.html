About

How I got here, and what I'm useful for.

Twelve years building enterprise systems for electric cooperatives — billing, meter reading, collection, network GIS, payroll and fleet. In practice I have been solving the same two problems that entire time, across two generations of hardware: get an accurate reading out of the field, and turn it into a bill that reconciles. Windows Mobile handhelds became Android; VB6 gained C# and .NET beside it; the problem did not change.

On the data side it is Microsoft SQL Server — design, stored procedures, query optimization, and snapshot and merge replication keeping instances in step on local infrastructure rather than in the cloud. Around that sits the integration work utilities actually need: AMI/HES, DLMS/COSEM, RAP data exchange, SMS gateways. More recently I have been building AI infrastructure around that data: local LLMs with Ollama, RAG over a vector database, and agents in Python and FastAPI.

01 Penelco MRBS

Peninsula Electric Cooperative

Android

Meter Reading & Billing System

The field app readers carry house to house. Opens on the bill month with total, read and pending consumer counts — 1,263 on the route shown — then takes the reading and computes the bill on the spot. Field findings are logged against the consumer, and the day exports to a transactions file with local backup and restore behind it.

02 Billing & Collection

Peninsula Electric Cooperative

Desktop

Total Utilities Billing System

The desktop system the billing cycle actually runs on, integrated directly with the Android meter reading app above. Charges, consumers and the meter gateway feed reading and commit; then print bill, posting, collection, remittance, ledger and adjustment — the full path from a field reading to money received and reconciled.

VB6 · Microsoft SQL Server

03 PENELCO GIS

Peninsula Electric Cooperative

Bataan

Distribution network GIS

Every asset on the network, on one map: 1,504 fiber poles, 27 substations and 1,449 69 kV nodes, with cable routes and province, municipality and barangay boundaries. Poles are graded good through critical, so the map doubles as a maintenance queue. A live telemetry panel tracks uptime, system load, throughput and servers up.

Google Maps

04 Bataan Tracking

Peninsula Electric Cooperative

Web

Personnel tracking with dispatch radio

A live map of crews across the Bataan service area, each one carrying a state — working, on break, emergency, inactive, off duty. Main office monitors every channel and holds to talk into a single town, so only that crew hears the reply. Track history replays a person's day, and boundary crossings are logged as crews move between municipalities.

05 PENELCO Payroll

Peninsula Electric Cooperative

Web

Semi-monthly payroll

Runs the cooperative's payroll for 309 employees on a first-half and second-half cycle. Computes gross to net with withholding tax, SSS, PhilHealth and Pag-IBIG, tracks readiness department by department, and blocks the period from locking while rows still need attention — missing monthly rates are named, not just counted. Withholding tax remittance runs off the same register.

08 Consumer AI agent

Swipe the canvas to follow the flow →

n8n

Consumer account agent for the mobile app

One webhook behind the mobile app, validated and then split on rules. Account questions fan out to three parameterised queries — consumers, arrears, payment — which merge, get mapped and repaired in a code step, then go to a Gemini agent with conversation memory and a reasoning tool. Policy questions take the other branch and are answered from a Google Doc instead. The database does the lookup; the model only has to phrase the answer.

n8n · Google Gemini

09 FB Page agent

Swipe the canvas to follow the flow →

n8n

Facebook Page agent

A single webhook doing two jobs: answering Facebook's GET verification handshake, and taking POSTed message events on the other branch. Events are filtered, normalised, and counted in Redis — with its own error path, so a cache miss does not swallow the message. The counter decides the route: either a Gemini agent answering with memory and a Google Doc for context, or a direct reply. Both go back out through the Send API.

n8n · Google Gemini · Redis · Meta Send API
